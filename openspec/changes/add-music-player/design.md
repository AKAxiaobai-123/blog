## Context

当前博客是 Astro 静态站点，顶栏由 `SiteHeader.astro` 提供，右侧仅有主题切换按钮；设计令牌集中在 `tokens.css`，全局样式在 `global.css`。参考图展示了 HOYO-MiX 音乐卡片的紧凑布局：圆形封面、歌名、进度条、上一首/播放/下一首；站点本身是绿松石 Firefly 视觉，音乐条需要融入这套体系，而不是做成独立的 App 级播放器。

实现约束：不引入新增运行时依赖，不改变内容模型，移动端不能遮挡导航或造成横向溢出，无脚本环境下页面仍可读。

## Goals / Non-Goals

**Goals:**

- 在顶栏右侧提供常驻音乐条，所有页面一致可见。
- 支持播放/暂停、上一首/下一首、可拖拽进度条、当前/总时长显示。
- 内置 3-5 首演示歌单，数据集中在 `src/data/music.ts`，音频放 `public/music/`。
- 复用现有设计令牌，浅深双主题、紧凑圆角、44px 点击目标、移动端不溢出。
- 键盘可达、无脚本降级，减少动效偏好下不播放额外动画。

**Non-Goals:**

- 不做完整播放器页、歌词、音量、播放列表抽屉或循环模式。
- 不接入音乐平台 API、用户登录或后端。
- 不做跨页面持续播放（Astro 普通页面跳转会重载页面，浏览器也不允许无用户手势自动播放）。

## Decisions

### 用原生 `<audio>` + 组件内脚本，不引入播放器库

`MusicPlayer.astro` 内置一个隐藏的原生 `<audio>` 元素，脚本持有 `MusicTrack[]` 播放列表，用 `play()`、`pause()`、`currentTime`、`ended` 等标准 API 实现全部交互。备选方案是 Howler.js 等库，但静态博客只有 3-5 首本地音频，原生 API 已足够且零依赖。

### 歌单数据独立成 `src/data/music.ts`

仿照 `src/data/demo.ts` 的类型化写法，定义 `MusicTrack`（id、title、artist、src、coverTone），组件从数据模块导入。后续替换真实歌曲只需改数据与音频文件，不改组件。封面先用强调色渐变占位（同作者头像占位策略），不引入二进制图片。

### 进度条用原生 range input

进度条使用 `<input type="range">` 并实时同步 `timeupdate`；拖动时先显示目标时间，`change` 后写入 `audio.currentTime`。比手写指针事件更易做键盘操作与无障碍（`aria-label`、`aria-valuetext`）。

### 播放状态轻量记忆

把当前曲目索引与进度写入 `localStorage`，页面重载后恢复上次曲目与进度，但不自动播放（遵守浏览器自动播放策略）。切歌、结束自动下一首，列表最后一首播完即停止。

### 顶栏集成与响应式

音乐条作为 `SiteHeader` 右侧第二控件，与主题切换并列；宽屏显示完整条（封面、标题、控件、进度），窄屏折叠为“封面 + 播放/暂停 + 上一首/下一首”紧凑胶囊，进度条保留最小宽度；导航仍可换行且互不重叠。

### 无脚本与渐进增强

组件先渲染静态曲目信息与禁用状态控件；脚本执行后给容器加 `data-enabled`，再启用按钮与进度条。`<noscript>` 中列出歌单文件名，保证无脚本环境不出现“点了没反应”的控件。

## Risks / Trade-offs

- 本地音频文件体积与版权 → 演示期使用短小的免版权音频并明确来源，后续替换真实歌单。
- 页面跳转会中断播放 → 通过 localStorage 恢复曲目与进度；文档中说明这是静态站的预期行为。
- 顶栏变宽挤压导航 → 音乐条用固定上限宽度并在窄屏折叠，导航保持换行且点击目标不低于 44px。
- 拖动进度条频繁写 storage → 只在暂停、切歌和页面卸载时持久化，`timeupdate` 仅更新 DOM。

## Migration Plan

按顺序实现 `src/data/music.ts`、`public/music/` 音频资源、`MusicPlayer.astro`、顶栏接入与 `global.css` 样式；执行 `astro build` 验证桌面、移动端、暗色模式与无脚本降级。回滚方式：还原顶栏接入提交，删除组件与数据文件即可恢复原状。
