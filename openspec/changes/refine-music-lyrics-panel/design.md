## Context

当前音乐条右侧为“歌词行 + 进度行 + 时间”的纵向堆叠，歌词行宽度受进度行内容影响，进度条没有延伸到时间文字边缘，右侧留白与对齐不稳定；同时只有演示曲目有歌词，缺失歌词时只显示“暂无歌词”。用户希望歌词区与进度条协调排布、歌词真正可见，并提供按钮平滑缩放歌词与进度条。

实现约束：Astro 静态站点、无新增依赖、音乐条整体宽度保持当前 `max-width`（约 26rem），顶栏导航与移动端无溢出行为不回归。

## Goals / Non-Goals

**Goals:**

- 歌词行、进度条、时间共享统一宽度与对齐网格，进度条延伸至时间文字边缘。
- 歌词行有独立且充足的显示空间，播放/拖拽时更新当前句，过长省略号截断。
- 无歌词、音频未就绪时显示清晰占位文案，不再出现“显示不出来”的状态。
- 新增展开按钮：点击后歌词与进度条平滑缩放，再次点击恢复，带 `aria-expanded`。
- `prefers-reduced-motion` 下直接切换，不播放过渡动画。

**Non-Goals:**

- 不做完整歌词面板、歌词滚动或 LRC 解析。
- 不改变音乐条整体宽度与顶栏布局。
- 不处理歌词版权内容，只保证授权歌词就位后可直接显示。

## Decisions

### 右侧区域改为“歌词行 + 进度行”的独立列布局

`.music-progress` 保持纵向列：歌词行 `flex: 1` 且 `min-width: 0`，进度行内 range `flex: 1` 填满剩余宽度，时间固定右对齐。歌词行不再被 range/time 的 min-content 压缩，进度条自然延伸到时间左侧。

### 歌词文本约束

歌词行使用 `white-space: nowrap`、`text-overflow: ellipsis` 与 `overflow: hidden`，在窄屏与展开态下都不会撑宽音乐条；无歌词数据时由脚本统一显示“暂无歌词”，音频错误时显示“音频待补充”。

### 展开按钮通过 class 切换 + CSS 过渡

在音乐条右侧增加一个展开按钮，点击切换根容器的 `is-expanded` class；歌词行与进度行使用 `transform: scale()` 与字号/高度微调实现平滑缩放，`aria-expanded` 同步状态。备选方案是动画高度展开，但会改变音乐条外框尺寸，与“保持宽度不变”冲突。

### 减少动效降级

`@media (prefers-reduced-motion: reduce)` 下关闭 `.music-player` 内相关过渡，展开态直接呈现。

## Risks / Trade-offs

- 缩放可能造成相邻元素视觉重叠 → 缩放比例控制在 1.05 以内，并保留容器内边距。
- 歌词行文字较长时截断 → 使用省略号，展开态适当提高字号但仍单行。
- 无歌词时页面看起来“没实现” → 占位文案明确区分“暂无歌词”与“音频待补充”。

## Migration Plan

按顺序更新 `MusicPlayer.astro`（结构 + 展开按钮 + 脚本）、`global.css`（布局、对齐、过渡与减少动效）、`music.ts`（如需补充歌词），执行 `npm run build` 并用桌面、移动端、暗色与无脚本场景验证，随后提交并推送 `dev`。回滚方式：还原音乐条组件与样式提交。
